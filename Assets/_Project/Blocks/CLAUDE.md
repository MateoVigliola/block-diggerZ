# Blocks (core block dropper)

Namespace `BlockDiggerz.Blocks`, asmdef `BlockDiggerz.Blocks` (references `BlockDiggerz.Input`, `BlockDiggerz.DebugTools`).

## Pieces
- `PieceDefinition` (ScriptableObject, `Data/Pieces/Piece*.asset`): id, box size, spawn cells inside a square box (y up). Every rotation keeps the same cell order. Clockwise rotation turns the box: `(x, y) -> (y, box - 1 - x)`. Standard shapes use box 3, I uses 4, O uses 2.
- `PieceSet` (`Data/StandardPieceSet.asset`): the 7 pieces. `PieceBag` deals each piece once per bag.
- Tags: `PieceTag` assets (`Data/Tags/`). Every piece lists its tags; only `Basic` for now. Board cells keep their `PieceDefinition`, so tags survive locking. Compare tags by asset reference.

## Block colors
- `BlockColor` assets (`Data/Colors/`: Red, Blue, Green, Yellow, Purple, Orange) have an id, a tint and an optional Sprite. With a sprite, `BoardView` draws that color with a runtime Tile made from it (untinted) and `PiecePreviewView` uses it as the cell image; without one, the shared `BlockCellTile` is tinted. The ghost always uses `GhostCellTile` tinted with Tint. Matching compares assets by reference. `BlockPalette` (`Data/BlockPalette.asset`) orders them; a run uses the first `BlocksRules.ColorCount` (4, minimum 3). A difficulty mode should set the count later.
- `Core/PiecePainter` paints each piece when it enters the NEXT slot (seeded with the run seed): 2 or 3 colors, at most 2 blocks per color, a repeated color on touching blocks (so 2+2 or 2+1+1), uniform over all valid paintings. A T can only be 2+1+1. `Core/PaintedPiece` holds a shape plus one color per cell; the falling, next and stored pieces are painted pieces.
- `BoardGrid` keeps a color per cell next to the piece. `Core/ColorMatchFinder` finds straight row or column runs of at least `MinColorMatch` (3), no bends; a block in a cross is removed once and scored per run. Full rows do not clear.
- `Core/BlockGravity`: each block is resting or falling (a bool array kept between steps). Touching same-colored blocks of the same state (any piece) form a group, so a falling group never sticks to resting blocks of its color on the way down; unpainted blocks are single groups. A group rests if any block is on the floor or on a resting block of another group; the rest fall one row per step, groups on falling groups included. Pieces split by color as they lock.
- `Core/ClearResolver`: finds color matches among resting blocks only (falling blocks never match), scores `ColorBlockScore` (10) per block, and only removes them (`BoardGrid.Remove`); gravity fills the gaps.
- Settling (`BlocksGame`): after a lock there is no player piece. After every change, matches among resting blocks are checked first: deleting takes priority over falling. Otherwise groups fall one row per `PlacedFallInterval` (`GravityInterval` divided by `PlacedFallSpeedMultiplier`, 2 by default). Matches flash for `ClearStepDuration` (cells in `ClearingCells`, flashed by `BoardView`) and are removed, then falling resumes, until nothing falls and nothing matches (chains). Then the next piece spawns. `IsSettling`, `IsBlocksFalling`, `IsClearing` expose the phase.

## Rules and loop
- `BlocksRules` (`Data/BlocksRules.asset`): default 10 x 20 board plus 2 hidden rows, gravity, soft drop, lock delay, auto shift delay and repeat, seed.
- `BlocksGame`: spawn centered with the top row on the top visible row; rotation clockwise (E/Up) or counter-clockwise (Q); hard drop (W) locks at once; the board settles (see Block colors); spawn overlap means game over; R restarts. Reads input only through `GameInput`.
- Rotation push (`Core/RotationPush`): a blocked rotation tries offsets in order (1 sideways away from what blocks, 1 the other way, 2 away, 2 the other way, then 1 up, then 1 up plus 1 sideways each way) and takes the first that fits; never down. Limits: `MaxSidewaysPush`, `MaxUpPush`.
- Lock delay (`Core/LockDelayTimer`): counts only while resting. A sideways move or rotation while resting gives back `LockExtensionBonus` (never past the full `LockDelay`), at most `MaxLockExtensions` times. Reaching a lower row than before restarts time and count.
- Store (`Core/PieceStore`): Space (or gamepad left shoulder) stores the falling piece; the stored piece (or the next bag piece the first time) spawns at the top. Locked from a store until the next piece locks. Reset on a new run.
- `BoardView` draws with three tilemaps (Background order 0, Ghost order 1, Blocks order 2), redrawing when `BlocksGame.Version` changes. The Ghost layer is a see-through copy of the falling piece at `BlocksGame.LandingPosition` (from `BoardGrid.LandingOffset`), tinted with its block colors; its sprite `Art/GhostCell.png` holds the bottom-up fade. `BlocksHud` (UI Toolkit) shows the STORE box left of the board (dimmed with `hud-store--locked` while locked, key hint from `GameInput.StorePieceBindingText`), SCORE and the NEXT box right of the board, and the game over panel. Piece boxes are drawn by `PiecePreviewView`, centered by `Core/PiecePreviewLayout` in a 4 x 4 grid.

- Board size (`Core/BoardLayout`): `BlocksGame.SetBoardSize(width, height)` clamps to 4-30 wide and 8-40 tall, rebuilds the board and restarts the run (levels call it at level start). `BlocksGame.BoardWidth` and `VisibleHeight` are the live size; everything reads those, not the rules. `BoardView` moves the BoardGrid so the visible board is centered on its camera (which never moves or zooms) and exposes `BoardWorldRect`; `BlocksHud` places STORE `_sideGap` left of the board and SCORE / NEXT the same gap right of it, top-aligned with the board.

## Debug menu section "Blocks"
Readouts: State, Piece, Position, Rotation, Landing, Lock timer, Extensions used, Tags, Block colors, Next, Stored, Can store, Score, Color blocks cleared, Settling, Colors in play, Pieces locked. Toggle: Pause gravity. Readout: Board size. Buttons: Board width -1 / +1, Board height -1 / +1, Board size reset (each restarts the run), Clear board, Fill bottom row (I gap), Color match (3), Color chain (2 steps), Game over, Restart run, Store piece, Spawn I/O/T/S/Z/J/L. Filled rows use shifted colors so they never match by themselves; `BlocksGame.PlaceBlock` plus `ClearBoardNow` set up any color case.

## Tests
- `Tests/EditMode`: board, rotation, bag, piece data and tags, rotation push, lock delay timer, piece store, preview layout, painting (`PiecePainterTests`), color matches (`ColorMatchTests`), board size and centering (`BoardLayoutTests`), groups and falling (`BlockGravityTests`), settle-and-clear chains and score (`ClearResolverTests`). The `BlocksGame` settle timing itself is only covered by PlayMode tests and playtesting. `ColorTestBoard` builds boards from text rows.
- `Tests/PlayMode/BlocksInputTests`: keyboard-driven controls through the Game scene.
